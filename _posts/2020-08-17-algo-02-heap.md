## 🇰🇷 문제 상황
요청 시각과 소요 시간이 있는 작업들을 한 대의 디스크가 처리할 때, **평균 대기 시간을 최소화**하는 스케줄을 구합니다. (프로그래머스 "디스크 컨트롤러")

## 아이디어
- 디스크가 비는 순간마다 **그 시점까지 요청된 작업 중 소요 시간이 가장 짧은 것**을 고릅니다.
- "가장 작은 것을 반복해서 꺼낸다"는 요구는 정렬을 매번 다시 하는 대신 **힙**으로 풉니다. 꺼내기와 넣기가 둘 다 O(log n)입니다.

```mermaid
flowchart LR
  J[요청 시각순 대기열] -->|현재 시각 이하만| H[(힙: 소요 시간 기준)]
  H -->|가장 짧은 작업| E[실행, 현재 시각 갱신]
  E --> J
```

## 핵심 코드
```python
import heapq as hq
from collections import deque

def solution(jobs):
    # (소요시간, 요청시각) 튜플로 바꾸고 요청시각순으로 정렬
    pending = deque(sorted([(d, s) for s, d in jobs], key=lambda x: (x[1], x[0])))
    delay = []                                 # 대기 중인 작업(힙)
    hq.heappush(delay, pending.popleft())
    now = total = 0
    while delay:
        amount, start = hq.heappop(delay)      # 가장 짧은 작업
        now = max(now + amount, start + amount)
        total += now - start                   # 요청 후 끝날 때까지 걸린 시간
        while pending and pending[0][1] <= now:
            hq.heappush(delay, pending.popleft())
        if pending and not delay:              # 디스크가 놀았다면 다음 작업을 가져온다
            hq.heappush(delay, pending.popleft())
    return total // len(jobs)
```

## 배운 점
- 힙에 **튜플을 넣으면 첫 원소 기준**으로 정렬됩니다. 그래서 (소요 시간, 요청 시각) 순서로 넣었습니다.
- 처리 도중 **디스크가 노는 구간**(대기열이 비는 경우)을 따로 처리하지 않으면 틀립니다. 이 케이스가 틀리기 쉬운 지점입니다.
- 복잡도: O(n log n).

## 🇺🇸 Summary
For the "disk controller" problem, always run the shortest job among those already requested. A min-heap (`heapq`) gives O(log n) push/pop, and the idle-disk case needs explicit handling. Overall O(n log n).
