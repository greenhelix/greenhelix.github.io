## 🇰🇷 DP를 쓰는 신호
같은 부분 문제가 **반복해서 나오고**, 큰 문제의 답이 작은 문제의 답으로 만들어질 때입니다. 풀이는 항상 **상태 정의 → 점화식 → 초기값** 순서입니다.

## 1로 만들기 (백준 1463) — 1차원
`dp[i]` = i를 1로 만드는 최소 연산 횟수.
```python
n = int(input())
dp = [0] * (n + 1)
for i in range(2, n + 1):
    dp[i] = dp[i - 1] + 1
    if i % 2 == 0: dp[i] = min(dp[i], dp[i // 2] + 1)
    if i % 3 == 0: dp[i] = min(dp[i], dp[i // 3] + 1)
print(dp[n])
```
큰 수에서 작은 수로 내려가는 탐욕적인 방법(3으로 먼저 나누기)은 틀립니다. 작은 수부터 **모든 경로의 최솟값**을 쌓아야 합니다.

## 가장 긴 증가하는 부분 수열 (백준 11053) — O(n²)
`dp[i]` = i번째 원소로 끝나는 LIS 길이. 앞의 더 작은 원소 j 중 `dp[j]` 최댓값에 1을 더합니다.
```python
dp = [1] * n
for i in range(n):
    for j in range(i):
        if s[i] > s[j]:
            dp[i] = max(dp[i], dp[j] + 1)
print(max(dp))
```

## 평범한 배낭 (백준 12865) — 2차원 표
`dp[i][j]` = 앞의 i개 물건으로 무게 한도 j일 때 최대 가치. 물건 i를 **넣거나 안 넣는** 두 경우 중 큰 값입니다.
```python
for i in range(1, n + 1):
    w, v = weight[i - 1], value[i - 1]
    for j in range(1, k + 1):
        if j < w:
            dp[i][j] = dp[i - 1][j]
        else:
            dp[i][j] = max(dp[i - 1][j], dp[i - 1][j - w] + v)
```
복잡도 O(N·K).

## 배운 점
- 점화식을 말로 먼저 쓰고 코드로 옮기면 실수가 줄었습니다. 상태의 의미가 모호하면 거의 틀렸습니다.
- LIS는 이분 탐색으로 O(n log n)까지 줄일 수 있지만, 이 저장소의 풀이는 O(n²)입니다.

## 🇺🇸 Summary
DP means defining the state, the recurrence, and base cases. Three templates: 1-D table (min operations to reach 1), O(n²) LIS, and a 2-D table for 0/1 knapsack (O(N·K)). Greedy dividing fails for "make it 1"; build from small values. LIS can be O(n log n) with binary search, but my solution is the O(n²) version.
