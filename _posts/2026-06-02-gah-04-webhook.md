## 🇰🇷 문제
사람이 외부 테스트 시스템의 결과를 보고 수동으로 옮겨 적던 작업을 없애고 싶었습니다. 외부 시스템에서 발생하는 이벤트를 Webhook으로 받아 협업 보드에 자동으로 올리는 기능을 설계했습니다.

## 접근와 막힌 점
실제로 붙여보니 예상과 다른 점이 많았습니다.
- Webhook 본문이 빈 값으로 오는 경우
- 필드명이 목적지 스키마와 안 맞는 경우
- 목록 조회 API의 개수 값이 항상 0으로 오는 경우

매번 "실제로 오는 데이터를 까보고 맞춰나가는" 식으로 해결했습니다. 예를 들어 헤더에서 서버 주소를 추출해 직접 API를 재조회하는 대체 경로를 넣는 식입니다.

## 결과
연결 진단 기능(포트 바인딩/방화벽/로컬 상태/외부 API 연결을 순차 점검)과 "테스트 훅 발송" 버튼(더미 요청으로 전체 파이프라인을 즉시 검증)을 추가해서, 운영 중 "왜 안 올라가지"를 바로 자가진단할 수 있게 만들었습니다.

## 배운 점
이후 오동작 리스크 때문에 "자동 시작은 기본 비활성, 사용자가 직접 켜야 한다"는 원칙으로 바꿨습니다(이 결정의 배경은 8편에서 다룹니다). 외부 시스템 연동은 문서보다 실제로 오는 요청을 먼저 믿어야 한다는 것도 배웠습니다.

## 🇺🇸 Summary
Wired up a webhook to auto-record events from an external test execution system instead of manual copy-paste. Reality didn't match the spec — empty bodies, mismatched field names, a list API that always reported zero — each fixed by inspecting actual incoming payloads rather than trusting documentation, including a fallback that re-queries the API using a server address extracted from the request header. Added a step-by-step connection diagnostic and a "send test hook" button for self-diagnosis in production, and later defaulted auto-start to off for safety.
