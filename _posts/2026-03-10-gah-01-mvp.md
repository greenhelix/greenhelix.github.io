## 🇰🇷 문제
Android 인증 테스트 모음을 돌리려면 매번 터미널을 열고 환경변수를 맞추고 긴 명령어를 직접 입력해야 했습니다. 여러 PC에서 반복하다 보니 "이번엔 어떤 버전 경로였지", "왜 adb가 안 잡히지" 같은 소모적인 문제가 끊이지 않았습니다.

## 접근
Flutter + Riverpod, feature-first 구조로 앱 뼈대를 잡고 "실제로 테스트를 실행해서 결과를 본다"는 한 가지에 집중했습니다.

- 버전 디렉토리만 입력하면 실행 파일 경로를 자동으로 찾는 경로 탐색
- adb/Java/Python/SDK Manager 상태를 PASS/FAIL로 보여주는 환경 점검
- 콘솔을 직접 띄워 인터랙티브 입력까지 지원하고, 결과 요약 패턴을 파싱해 PASS/FAIL/Total 집계

가장 끈질기게 반복된 버그는 "셸에서는 되는데 앱에서는 안 된다"였습니다. 데스크톱 앱 프로세스는 로그인 셸의 프로필 설정을 읽지 않아, 터미널에선 잘 잡히던 adb/sdkmanager가 앱 안에서는 안 잡혔습니다.

## 결과
해결은 두 단계로 정리했습니다.
1. 실행 파일을 전체 경로로 직접 지정
2. 그래도 안 되면 로그인 셸로 명령을 감싸서 실제 셸 환경을 그대로 상속

이 패턴은 이후로도 "환경 불일치" 계열 버그의 표준 해법이 됐습니다. 배포 체계도 이 구간에서 처음 자리잡았습니다: 최초 설치 패키지 + 압축 아카이브 자동 업데이트, 빌드 스크립트화(수동 압축 금지 — 이후 내내 지켜진 규칙의 시작점), 저장소 기반 자동 업데이트.

## 배운 점
"일단 되게 만들기"가 아니라 "배포판에서도 똑같이 되게 만들기"가 핵심이었습니다. 로컬 개발 환경과 실제 배포 환경의 차이를 원인까지 추적해서 재현 가능한 해법으로 만든 것이 이후 전체 개발 스타일의 기준이 됐습니다.

## 🇺🇸 Summary
Built a desktop app (Flutter + Riverpod) to automate running a suite of Android compliance tests, replacing repetitive manual terminal setup across multiple machines. The recurring bug was environment mismatch — the app process didn't inherit the login shell's profile, so tools visible in a terminal weren't found by the app. Fixed by using absolute paths and, as a fallback, wrapping commands in a login shell. This "match the deployed environment, not just the dev one" lesson shaped the rest of the project.
